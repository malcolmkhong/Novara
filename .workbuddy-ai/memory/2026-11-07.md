## 修正：Cloud Run 免费额度口径（用户质疑后复核，已回写 DEPLOYMENT-GOOGLE.md）
- **承认上一条表述不精确**：不是「Cloud Run 产品要钱」，而是「把它配成能跑 Novara `after()` 后台任务的形态会用超免费额度」。文档 §0/§2.1/§2.2/§2.4/附录 A 已改，新增 §2.6「Cloud Run 什么情况下用 / for what」+ 附录 D 风险 12/13。
- 官方口径**互相冲突**：`cloud.google.com/free` Cloud Run request-based = 180,000 vCPU-s + 360,000 GiB-s + 2M 请求/月；`cloud.google.com/run/pricing` Free tier = 342,857 vCPU-s + 642,857 GiB-s（Worker pools 另池 384,204/728,744）；第三方 Billing Catalog = instance-based 240,000/450,000。**池不叠加、不滚存**。1 vCPU 常驻 = 2,592,000 vCPU-s → 超额 7.6–14.4 倍（原写「10 倍」是单一口径）。$40–44/月是估算，以账单为准。
- **v1 漏掉的便宜选项**：request-based + `min-instances=1` 空闲费率 $0.0000025/vCPU-s（active $0.000024），约 $10/月 —— 但 CPU 仍只在请求期间分配，`after()` 跑不动。**便宜 ≠ 能用**。
- **Free Tier ≠ 抵扣金**：官方 Free Tier 表 20+ 产品、按月额度、无到期日、超额即计费、不滚存；$300/90天（用户的 RM1223/3个月）是限时试用信用。**官方 Free Tier 表里没有 Cloud SQL**，只有 30 天 free trial 实例。
- **Cloud Run 在这项目的正确用法（§2.6）**：A 拆无状态端点（scale-to-zero，$0）/ **B 把 Agent 执行器改成 Cloud Tasks → Cloud Run Jobs（任务驱动，实例只活任务时长，12min×10次/天≈7,200 vCPU-s，$0）** / C 整站常驻（$40–44）。**A 和 B 都硬前置「DB 外置」**，而 Cloud SQL 无免费档 → 计算可 $0，数据库 ~$10/月跑不掉。B 的代码基础已具备：`claimLease` CAS / `leaseEpoch` fencing / `healStaleRuns()` / `resume`，SSE 路由已是每 1.2s 查 DB；要改的是把 `setInterval` 心跳与内存 checkpoint 外部化。
